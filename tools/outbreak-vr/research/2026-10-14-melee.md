# Melee in File #1: the game's swing, its hit test, and putting the hit on the VR weapon (2026-10-14)

Branch `melee`. Static work on RAM dumps of File #1 (J's Bar savestates 1-9 and two dumps of slot 5 taken during this
session; none committed) and live offline runs of the `run-melee` dev build, headset-free (no OpenXR runtime,
`PCSX2_VR_TEST_INPUT=1`, scripted pad buttons over PINE), normal speed (the game counter ran at 55-60 a second).

Evidence words: **verified** = read from the code or memory; **checked offline** = seen live in a headset-free run;
**assumed** = reasoned, not measured.

**Caveat for every live melee number below:** no savestate has a melee weapon equipped, and equipping one needs a menu
confirm, which the tools never do. The live runs therefore *poked* the equip offline (never saved): the local record's
`+0xC7C` set to a floor item's record (iron pipe 11, butcher knife 2, scrub brush 13, wooden pole 21, spear 53 in slot
5's item table), and that record's `+0x1C` (its weapon object) pointed at the object the equipped 45 Auto already had in
the hand. The game then runs its own swing, attack object and hit test for that weapon type, but the "weapon" whose
matrix it follows is the 45's object in the hand, not the real pipe model. Everything the override touches is the same
either way (it replaces that matrix). Alex should still confirm with a real equip.

## Short answer

- **The swing**: with the weapon raised (stance `+0x08` = 2, aim idle sub-action `+0x09` = 1), Circle (pressed bit `0x20`
  of `+0xF78`) makes `FUN_005562F0` choose the attack: guns sub-action 2, **melee weapons and bare hands sub-action 3**.
  The swing plays a motion (`+0x1F2`, e.g. 596 for the iron pipe), and the motion's **event script** decides when the hit
  is live: at one frame it spawns an **attack object** that follows the weapon's own world matrix, at a later frame it ends
  it.
- **The hit test**: each frame `FUN_005A9DB0` walks the attack nodes and tests each node's shape against the enemies. A
  melee weapon's shape is a **capsule along the weapon model's X axis** (pipe: from x = +40 to -60 cm, radius 30 cm) or a
  **sphere** (knives: r 30 cm, 10 cm down the blade), placed by the attack object's matrix, which `FUN_00552CF0` copies
  from the weapon object every frame. A hit stages damage in the enemy's `+0x138`; `FUN_0060F0C0` takes it off HP.
- **The override (checked offline)**: a 39-word code cave at `0xFE000` plus 5 patched words makes the local player's
  melee attack object take its matrix and position from a block the host writes (`0xFF000`: the VR weapon's pose in game
  space) instead of from the weapon object, while that block is fresh. Placed 3 m from the zombie the same swing misses
  (no HP write); without the override it hits; placed on the zombie it hits a zombie 2 m out of Kevin's reach. Damage,
  stagger and hit reaction are the game's own.
- **Timing**: the stock hit window opens 14-32 motion frames (0.23-0.53 s) after the press. One immediate per motion
  moved to frame 2 opens it about 70 ms after the press (checked offline: press 3.30 s, attack object 3.37 s, hit 3.40 s).

## 1. The input and the state bytes (local record, File #1 record `0x476DD0`, stride `0x10E0`)

Verified (code) and checked offline (live reads at 30-60 Hz):

| Offset | What |
|---|---|
| `+0x08` u8 | stance: 1 normal, 2 weapon raised, 3 hit/stagger (Kevin after a zombie hit), 5 grabbed |
| `+0x09` u8 | sub-action in the stance. Stance 2: 0 raising, 1 aim idle, 2 shot, **3 melee swing**, 7 lowering, 8 end of an auto attack, 10 target switch, 11-13 class specials (`FUN_005562F0`) |
| `+0x0A` u8 | phase inside it. Swing: 20 then 21 while it runs; **24** after an iron pipe or wooden pole connects (not the knife, not the brush or spear) |
| `+0xF78` u32 | buttons pressed this frame: `0x20` Circle, `0x400` R1, `0x800` L1 (checked offline) |
| `+0xF80` u32 | buttons held: `0x20` Circle, `0x400`/`0x40` R1 |
| `+0xCA8` u16 | the equipped weapon type (rewritten every aim frame from `+0xC7C` by `0x5C1240`) |
| `+0x1E4` | animation channel 0: f32 current frame `+0x00`, end frame `+0x04`, motion id u16 `+0x0E` (`+0x1F2`) |
| `+0x115` u8 | bit 0: "attack over", set by the motion's end event, read by the attack object |

- **Stance 2 dispatcher** `FUN_00554EF0` (pointer at `0x6DEC98`, the stance table `0x6DEC90`) jumps through `0x7096C0`
  by sub-action: 1 `FUN_00555210` (aim idle: Circle -> `FUN_005562F0`, L1 -> target switch), 2 `FUN_00555610` (shot),
  **3 `FUN_00555770` (swing)**, 7 `FUN_00555B30` (lower).
- **`FUN_005562F0`** (Circle while aiming), in order: weapon type 0 (bare hands) -> sub 3; the item's count `+0x24` = 0 ->
  nothing (or a dry click for a gun, flag `0x10`); David (`+0xB98` = 4) with flag `0x400` -> 13; class byte 6 (spray) -> 11;
  flag `0x40000` -> 12; **flag `0x10` (a gun) -> 2**; a throwable (`0x583E30` flag `0x1000000`) -> 4; Mark (`+0xB98` = 1)
  with flag `0x10000` and `+0xBA4 & 0x800` -> 14 (his own swing); **else 3**.
- **`FUN_00555770`** (sub 3, every frame) only watches the end: once `+0xCE2 & 0x80` (the motion's cancel point) is set it
  goes back to aim idle if R1 is held (a new Circle chains another swing) or returns. An auto-repeat weapon (flag `0x8`)
  ends with sub 8 when Circle or R1 is let go.
- **Swing types**: the motion is picked by weapon class, not by input: iron pipe and wooden pole play 596, the scrub
  brush and spear 602, the butcher knife 265 (checked offline). The event script also has 597 and 598 next to 596 and
  603 and 604 next to 602 (verified); assumed: the up and down aims (`+0xBCD`) or other characters. No light or heavy
  input exists for Kevin; Mark's sub 14 is a character special.

## 2. The weapon-type table and the attack data

The weapon-type table (`0x6E5940` + 0x44 * type, the `hold` block's table is the same one 4 bytes in): u32 flags `+0x00`
(`0x10` gun, `0x400` blade, `0x10000` blunt or pole, `0x8` auto-repeat), class byte `+0x05` (1 knife, 2 handgun,
3 shotgun, 4 pipe, 5 long pole, 6 spray, 7 magnum, 8 rifle), `+0x06` its own index (the attack id).

File #1's melee types (verified, slot 6 and the two slot-5 dumps):

| Type | Item | Flags | Class | Attack shape | Damage `+0x14` | Hit window (motion: frames) | Seen on the slot-5 zombie (600 HP) |
|---|---|---|---|---|---|---|---|
| 33 | Butcher Knife 102 | `0x405` | 1 | sphere r 30 at (-10, 0, 0) | 40 | 265: 14-22 | 600 -> 545 |
| 32 | Kevin's knife 407 (David's?) | `0x405` | 1 | sphere, the same | 40 | assumed 265 | - |
| 34 | Iron Pipe 103 | `0x10005` | 4 | capsule (40,0,0) along -X, 100 long, r 30 | 100 | 596: 16-30 | 600 -> 540 -> 530 |
| 35 | Curved Iron Pipe 104 | `0x10005` | 4 | capsule (20,0,0), 80 long | 100 | assumed 596 | - |
| 41 | Scrub Brush 110 | `0x10005` | 5 | capsule (40,0,0), 120 long | 100 | 602: 32-40 | 600 -> 560 |
| 42 | Wooden Pole 111 | `0x10005` | 4 | capsule (20,0,0), 80 long | 100 | 596: 16-30 | 600 -> 550 |
| 44 | Spear 113 | `0x10005` | 5 | capsule (40,0,0), 120 long | 100 | 602: 32-40 | 600 -> 480 |
| 0 | bare hands | `0x80005` | 0 | sphere | 40 | not measured | - |

- **Attack parameters** (kind 0, the player's): `0x6E7C90` + 32 * attack id: `+0x00`/`+0x01` start delay and life
  (frames, `0xFF` = until ended), `+0x0E` the shape index into `0x6EBFA0` (8 bytes: u32 shape type, u32 pointer to its
  data), `+0x14` u16 damage, `+0x0A`/`+0x0B` age and repeat limits. The damage seen is not the table value: it is scaled
  (distance, hit zone or enemy type; not traced).
- **Shape data** (verified): type 3 = capsule: f32 x 3 a point P, f32 x 3 a direction D, u16 radius `+0x18`, u16 length
  `+0x1A`, u16 bone `+0x1C` (`0xFFFF`: the attack object's own matrix, which every melee weapon uses; otherwise a bone of the
  owner's model). The segment runs from P to P + D * length, in the attack object's frame. Type 2 = sphere: a point and a
  u16 radius. Guns use type 3 too: P (0, 0, 0), D (0, 0, 1), length 1000, radius 24: a 10 m ray. **So bullets resolve the
  same way** (this answers the open question in the 2026-10-13 shot note): `FUN_0062CF10` (the shot, from the shot
  pending bit 31 of `+0xBA0` in the character loop `FUN_00638850`) spawns the attack object with the gun object's
  muzzle and matrix.
- **Durability**: the item record's count `+0x24` (pipe 40, brush 30, wooden pole 15, spear 60, knives 1) did not change
  on any poked hit. Assumed: it is spent by another path (the real weapon object, or a hit on a human); not traced.

## 3. The chain from the press to the damage (verified, then checked offline)

1. **The event script.** `FUN_00543410` -> `FUN_005654D0` picks a script set by `+0xCE1` (0 with a melee weapon:
   `FUN_005661C0`; 2 with a gun) and dispatches on the motion id `+0x1F2`. Each motion lists events as calls with the frame
   in `a0`: `FUN_00565C80(frame, record, code, id)` fires when the channel's frame crosses `frame`
   (`FUN_00543460`). Code 2 = **spawn the attack** (`FUN_005521B0(record, record + 0x50, record + 0x38, +0xC7C)`), code 3 =
   set `+0x115` bit 0 (**end it**), code 1 = spawn attack id `weapon type` directly, code 0 = spawn attack id `a3`.
   The spawn-frame immediates (`addiu a0, zero, N` before the code-2 call), verified words:

   | Motion | Weapon | Spawn word | End frame |
   |---|---|---|---|
   | 265 | knife | `0x568534` = `0x2404000E` (14) | 22 |
   | 596 | pipe, wooden pole | `0x5694D8` = `0x24040010` (16) | 30 |
   | 597 | (variant) | `0x569550` = `0x24040010` (16) | 28 |
   | 598 | (variant) | `0x5695E4` = `0x24040016` (22) | 30 |
   | 602 | brush, spear | `0x5696A0` = `0x24040020` (32) | 40 |
   | 603 | (variant) | `0x56972C` = `0x24040026` (38) | 44 |
   | 604 | (variant) | `0x5697A4` = `0x24040028` (40) | 46 |

   The motion runs at 60 frames a second (checked offline: 596 is 86 frames, 1.43 s from the press to aim idle; 602 is 112).
2. **The attack object.** `FUN_005521B0` needs the item's weapon object (`item + 0x1C`, the model in the hand; floor
   items have none, so a poked equip without one swings and never hits: checked offline). It allocates an object
   (`FUN_00551E30`; updater `FUN_00552940` at `+0x14`, owner record at `+0x28`). For flags `0x10400` (blades, pipes,
   poles) it is **type 2**: position `+0x38` and matrix `+0x50` copied from the weapon object's `+0x200` and `+0x1C0`
   (`0x5523C4`-`0x552404`), life until ended, then `FUN_005A9960(object, weapon type, 0)` spawns the attack node.
   Guns are type 1 (3 frames, from the muzzle point and matrix passed in), throwables type 9.
3. **Following the weapon.** `FUN_00552940` (type 2 -> `FUN_00552CF0`) copies the weapon object's position and matrix
   into the attack object **every frame** (`0x552D8C`-`0x552DE4`) until the owner's `+0x115` bit 0 is set; then the object
   and its node end. The object's matrix is 4 x 4, row vectors (`v * M`, rows the model's axes, unit length, row 3 the
   position; `FUN_001913A0` is `x row0 + y row1 + z row2` on VU0), checked on the 45's object.
4. **The test.** Attack nodes are a list at `gp - 0x5ED0` (`0x23BDA0`; gp `0x241C70`), allocated by `FUN_005A97C0` from a
   pool at `0x386750`: node `+0x08` the attack object, `+0x0C` live, `+0x0D` attack id, `+0x0E`/`+0x0F` delays, `+0x10`
   the shape, `+0x14` the parameters, `+0x1B` hit this frame, `+0x28` age, `+0x2A` kind. `FUN_005A9DB0` runs them each frame
   (from `FUN_005CDE40`) through the shape testers `FUN_005AA410` / `005AA9B0` / `005AAE60` / `005AB3C0` (types 1-4),
   which stage damage in the enemy's s16 `+0x138` (`FUN_00549EA0`, `0054AB30`, `0054B5C0`) and add to the player's damage
   statistics (`0x4747xx`).
5. **The damage.** `FUN_0060F0C0(enemy, attacker, ...)` subtracts `+0x138` from the enemy's HP (memwatch on the HP word:
   writer PC `0x60F108`, `a1` = the local record, after a shot and after every poked melee hit). The enemy then plays its
   own reaction (state `+0x08`/`+0x09` 3/x, knocked back: the distance grew 65 -> 275 cm after a 45 Auto shot) and a
   second node (attack id 122, owner the record itself) adds a push of about 10 HP.

**Enemies** (verified): `0x3FFCA0` + `0xD90` * n (the stride is `0xD90`, not `0x1F0`), n up to 63: byte `+0x00`
present, `+0x08`/`+0x09` state, s16 HP `+0x544` and max `+0x546` (dead ones read negative), `+0xC94` bit 0 dead, `+0x551`
a node index. Slot 5's zombie is n = 49 (`0x429530`); n 44-49 are present in J's Bar. The lock list `0x71A030` (0x60 a
row) names the slots by index.

## 4. The override (implemented; checked offline over PINE with the same words)

Free RAM: `0x84000`-`0x100000` is zero in all twelve File #1 dumps (the gap between the EE kernel and the game ELF).
The cave sits at `0xFE000`-`0xFE0FC`, the host's block at `0xFF000`:

| Address | What the host writes |
|---|---|
| `0xFF000` u32 | `0x4D454C31` ("MEL1") while the override is armed, 0 otherwise |
| `0xFF004` u8 | the game counter u8 `0x48BF93` as it read it this poll (it counts 0-59, one a frame) |
| `0xFF008` u32 | the local record's address |
| `0xFF040` 16 x f32 | the VR weapon model's matrix in game space (rows: model X, Y, Z in game units per cm, then the position, 1) |
| `0xFF080` 3 x f32 | its position (the same as row 3) |

The block is laid out as a fake weapon object: base `0xFEE80` + `0x1C0` = the matrix, + `0x200` = the position.

- **Cave A** (`0xFE000`, 39 words), reached from `0x552D8C` (`j 0xFE000`; `0x552D90` its delay slot made a nop): with
  `a2` = the attack object's owner and `t0` the weapon object, it uses the fake object instead when the magic is set, the
  owner is the record at `0xFF008`, and the stamp is at most 6 game frames old (mod 60); then it copies position and
  matrix exactly as the original did and returns (`FUN_00552CF0` is a leaf).
- **Cave B** (`0xFE0A0`, 23 words), reached from `0x5523C4` (`jal 0xFE0A0` over `lw v1, 0(s0)`, its delay slot `0x5523C8`
  a nop, the second `lw v1, 0(s0)` at `0x5523E0` a nop): the same choice for the first frame, when `FUN_005521B0` builds
  the object; it returns the object to copy from in `v1` and does the `lwc1 f2, 0x200(v1)` it replaced.
- **Earlier window**: first done by setting the seven spawn frames above to 2 (`0x24040002`), which was shared with
  everyone who plays those motions (AI partners' swings went live sooner too). Since `meleecoop` the frame words stay
  stock and the seven `jal FUN_00565C80` after them call **cave C** (`0xFE100`, 22 words), which sets the frame to 2 for
  the local record only, under the same magic, owner and stamp test as A and B (`2026-10-14-melee-coop.md`).
- **What it never does**: it never writes an enemy or another record, never presses anything in a menu, and leaves every
  other attack object and every other character's hit window alone (owner checks). It runs only while first person is
  armed and `[VR] PhysicalMelee` is on; strictly offline, or online only with `PhysicalMeleeOnline` in private co-op
  while this console runs the room's enemies (`2026-10-14-melee-coop.md`).

over PINE, held raised with the bumper, swung down and forward through 120 degrees in 0.22 s; `e2e.py` in the session

stroke); the game's swing started 33 ms later.`; the attack object at (7968, 170, 13608), the host block at (7968, 172,

Seen there: the stroke counted on the wind-up (the hand going up and back fast enough), not the downswing. The hit
volume follows the weapon for the whole window (about 0.5 s), so the downswing still hits; a backswing into an enemy
behind you would hit too.

**Online (stated explicitly):** as built on `melee`, `PhysicalMelee` did nothing online at all (its presses, its block
writes and the caves were gated on strictly offline, like `SeamlessDoors`). `meleecoop` adds the separate
`PhysicalMeleeOnline` for private co-op after tracing how a hit reaches partners (below).

## 5. Co-op (traced statically in `2026-10-14-melee-coop.md`; not checked online)

Every console runs every player's swing from the state the attacker sends (a type-1 message as the swing starts) and
tests it against its own copy of the enemies; the console that runs the room's enemies (the first in NETAQ.BIN's list
for the room) alone kills and sends their HP and reactions, which the others take. The 20 callers of `FUN_0060F0C0` are
the enemy types' own damage states (`0x65956C` is one of them, not network code), and `FUN_0064C620` builds the player's
own messages (the lock target is in type 1; the type-2 heartbeat carries position, status and heading). So online the
swing may press the game's own attack, and the hit may follow the VR weapon only while this console is that master
(`[VR] PhysicalMeleeOnline`).
