# The game's own text in first person, and which of our cues stay (2026-10-22)

Branch `gamecues` (from `nightly` 0557a8d). Switch `[VR] GameText`, on by default. Alex wants Resident Evil Outbreak in
VR to use the game's own systems, not our overlays. So this branch makes the game's own text readable in first person,
and lets our cues give way where the game already says the same thing.

Labels: **measured** = seen in this branch's headset-free runs; **code** = read in the disassembly; **assumed** = not
checked.

## 1. Where the game's text was

File #1 has no persistent HUD. Its in-world text is part of its own 2D layer: speech subtitles (green, typed out from the
left), "HANDGUN Obtained" (centred), and examine and system lines. Screenshots of the emulator window (the
first-person picture, 512 x 448; rows given in 448-line space):

| Line | Rows (game's placement) | In the headset (100 deg tall view) |
|---|---|---|
| Subtitle "I hope everything's under control." (slot 7), "Maintain your composure." (slot 4) | 323-338 | about 36 deg below the line of sight |
| "HANDGUN Obtained" (slot 7, after the hand pickup) | 385-396 | about 41 deg below |

Both modes put that layer across almost the whole view:
- TrueStereo draws flat draws on a plane 1.5 m ahead, over 90% of the view both eyes share.
- Without TrueStereo, the first-person screen is sized to the camera's FOV, which `FirstPersonFov = Auto` widens to the
  headset's.

So the text sat at the bottom edge, where you have to look down to read it (measured, rows).

## 2. What GameText does

The game's 2D layer is drawn at `EyeProjection::kGameTextScale` (0.5) of its size, about the view centre:
- **TrueStereo on:** the flat plane spans 0.9 x 0.5 of the shared view (`GSRendererHW`, the flat-plane sizing). Menus
  keep 0.9 (`SpatialControls::MenuMode()`), and a screen split onto the menu panel keeps the game's placement, as before.
- **TrueStereo off:** the 2D draws' vertices (FST draws into the first-person multiview target) move toward the
  picture's centre (2048, 2048 in GS coordinates, the game camera's centre). This skips:
  - draws that fill the target (fades);
  - a screen split onto the menu panel;
  - anything while a menu is up.
  The draw area then becomes the scissor, as for TrueStereo's moved vertices.

Text, timing and windows stay the game's own. No game memory is written.

Measured, headset-free (`run-cues`, local LTO-off build, no OpenXR runtime, scripted input; the TrueStereo runs used
`PCSX2_VR_TRUESTEREO_TEST=0.064`, so they used the camera's own tangents):

| Run | Subtitle rows | "Obtained" rows |
|---|---|---|
| slot 7, GameText off | 323-338 | 385-396 |
| slot 7, GameText on, TrueStereo off | 274-281 | 304-310 |
| slot 7, GameText on, TrueStereo test | 269-275 | 296-301 |
| slot 7, GameText on, TrueStereo test, MenuPanel on | 269-275 | 296-301 (every shot from the first one after the prompt) |
| slot 4, GameText off / on (TrueStereo test) | 325-338 / 270-275 | - |

In the headset (assumed: a 90-100 deg tall view, tangent 1.0-1.19), that is:
- "Obtained" about 18-23 deg below the line of sight, a subtitle about 12-16 deg below;
- letters about 2 deg tall, against the toast's 1.1 deg.

The self-test (`Eye projection`, 5 new checks) holds both lines between 8 and 26 deg below on a 90-100 deg view, with
and without TrueStereo's 0.9.

Slot 5 shows the game's own virus gauge: a ring with "6.03%", in the bottom-right corner (measured, TrueStereo off).
So File #1 does have one HUD element outside the item screen, which the atlas did not see in the J's Bar captures.
GameText scales it with the rest of the layer: it moves from the corner to about 25 deg right and 15 deg below the
line of sight (assumed angles, from the rows). Nothing else differed between GameText on and off in slot 5: frame
differences above 60 grey levels were all in the gauge's two places.

Seen once: with `MenuPanel` off and TrueStereo off, the first shot after the take-it prompt showed the lines at the game's
size, because menu mode was still up. The next shot (0.6 s later) showed them scaled. With MenuPanel on, no such shot was
seen.

## 3. The game's own text window (0x540140) is not where these lines come from

The atlas (`2026-10-22-re-atlas.md`, section 2c) maps `FUN_00540140(msgId, kind, delay, duration, priority)`. Read in
the J's Bar dump (code):
- it creates the text task, whose update is `0x6844F0`;
- it stores the window's position from two `lui` constants: x 64.0 at `0x540200`, y 380.0 (`0x43BE`, not 381) at
  `0x540214`, into task `+0x70` and `+0x74`;
- the task's update passes them as ints to `0x687B60` (its only caller);
- `0x540140` has 6 callers, all its own wrappers.

A profile patch of the y constant (380 -> 300) was in for the first runs and read back live (`0x3C034396`). Neither the
speech subtitles nor "HANDGUN Obtained" moved, and the window flag `u8 0x48BF9A` stayed 0 through both (measured). They
come from another routine, not found in this pass; the atlas calls these "assumed from the call sites". The door and
`0x5400A0` system messages may still use `0x540140`, but they were not seen. The patch was dropped: the 2D-layer scale
places every line, whatever routine draws it.

Open: the routine behind the subtitles and "Obtained". Moving its own constants would let the game place them with no
GS work.

## 4. Our cues: which stay and why

| Cue | Where | Game equivalent | Now |
|---|---|---|---|
| Pickup cue toast "`<item>`  (A)" and its light tick | `ItemReach` (`PickupCue`) | None before the press: the game has no "can pick up" prompt; after Circle, its take-it prompt names the item | Kept before the press. Taken off as soon as a game screen is up (`HudCards::CancelToast`, logged "our toast is off"), so the game's prompt is the only text then. |
| "X Obtained" | - | The game's own line | We have no toast for it; the game's line is now placed for first person. |
| Pouch name toast | `BeltPouches` | None: our zones on the body | Kept. |
| Reload toasts (full, no ammo, walking, hints) | `ReloadDriver` | None: the game's L1 reload shows no text | Kept. |
| "Shake to break free!" | `CameraDriver` | None: the game's grab shows no prompt | Kept. |
| Wrist card (HP, virus, bleed, weapon, rounds) | `HudCards` | The ECG panel inside the item screen, and the virus gauge at times (slot 5) | Kept: there is nothing in play to prefer. A one-to-one version would show the game's own panel. |
| Recentered, controllers paused/back, online/co-op, presence | `CameraDriver`, `VRInput` | Not game messages | Kept: they are emulator messages. |

Not checked live: the cancel itself. In slot 7, the cue's 1.3 s toast had already ended before the scripted press, so
the cancel never ran. The HUD self-test covers it: only the named toast goes, at once, and only once.

## 5. Headset check

Slot 7, with TrueStereo on and then off:
1. Take the Handgun. "HANDGUN Obtained" and the speech subtitle should be readable without looking down, about a hand's width
   below where you look, and not blurred.
2. Slot 4: the speech subtitles.
3. Open the item screen: it should keep its size (MenuPanel) and the text should not jump.

If the text feels too small, raise `kGameTextScale` (0.5 to 0.6). If it is too close to the centre, lower it.
`GameText = false` restores the game's placement.
